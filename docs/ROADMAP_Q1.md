## 1. Rules for agents (read first)

1. **Scope.** Do only the task ID you were assigned (for example `T3.2`). If you find
   other problems, list them in your final report under "Found, not fixed". Do not fix them.
2. **Out of scope** (do not start, even if an audit suggests it): SD5 step resolution,
   N4 method-map verdicts, N5 more images, N6 competence-decoupled design, SD6-full
   `validate_metric()`, ViT or any non-CNN model, from-scratch watermark models,
   extra seeds, extra methods, Pattern Recognition reformatting, LaTeX version.
3. **No GPU runs and no long training by agents.** The author runs every Kaggle session
   and every laptop run longer than about 10 minutes, in his own terminal. Agents may run
   CPU smoke tests of a few minutes in a temp directory that they delete afterwards.
4. **Pre-registration comes first.** No SD3 or SD4 model or score is produced (not even a
   pilot) until amendment A3 and its predictions are committed **and** uploaded to Zenodo
   as a new version of record 10.5281/zenodo.24285532 (concept DOI 10.5281/zenodo.24285531).
   Never edit an existing prediction; only append dated notes.
5. **Existing results stay bit-identical.** New metrics, fills, settings and tables go into
   new columns or new files. Check with the bit-identity checker before every commit that
   touches `dose_response.py`, `xai/` or `results/`. The `original` and `pre_a2` model sets
   must reproduce exactly.
6. **Official title exactly** as above in every document (`.kiro/steering/project-rules.md`).
7. **No invented citations or numbers.** Every new reference is verified online with its
   URL recorded in the task report. Every number in the paper comes from a CSV.
8. **Sole author:** Md Junaid Faizan Shaikh, Khaja Bandanawaz University,
   ORCID 0009-0002-6565-1835.
9. **Never commit** `data/`, `checkpoint/dose/*.pt`, zips or `.agents/`. Commit specific
   files by name. Push to `origin main` only after an independent review approves.
10. **Time-box.** Each task has a budget (Section 3). If a task needs more than 1.5× its
    budget, or needs a design decision not written here, stop and ask the author.
11. **Kaggle notebooks** are generated by `kaggle/build_notebook.py`, never hand-edited.
    Old notebooks must stay byte-identical. Each session must fit in 11 h.

### Phase 2: pre-register SD3 and SD4

**T2.1 Amendment A3** in `docs/PREDICTIONS_amendments.md` and predictions in a new
`docs/PREDICTIONS_sd3_sd4.md`. Budget: 2–3 h. It fixes, before any SD3 or SD4 run:

- **SD3 design:** ROAD with noisy linear imputation (Rong et al., ICML 2022,
  https://arxiv.org/abs/2202.00449), MoRF and LeRF orders, 10 removal steps
  (10 %, 20 %, …, 100 % of pixels, or the exact grid of the reference implementation,
  stated in A3). Scored on the oracle maps already used (shortcut, object, size-matched,
  random, placebo) for every scored model: 100 images per model on the 28/32 px settings,
  50 images per model on CIFAR ResNet-18, Pet, SD1 and SD4. Same preference and decision
  rules as the existing metrics.
- **SD4 design:** content-coded watermark, as recommended in `docs/audit2/05_additions.md`
  §4.3: two different semi-transparent marks (one per class), same corner, about 24×12 px,
  opacity in 0.3–0.5 (exact values fixed in A3). Network `pet_resnet18_pretrained`
  settings unchanged. Reliance = model follows the other class's mark when swapped in.
  Oracle shortcut map = glyph stroke mask; placebo = the other class's mark mask; object
  oracle = Pet mask; size-matched control as for the patch.
- **SD4 pilot:** seed 7, doses 0 and +0.25 (2 models). **Dose rule** fixed in A3 before
  the pilot, for example: pilot r_c at dose 0 ≥ 60 → doses −0.5, −0.4, −0.3, −0.2, −0.1, 0;
  below 60 → −0.5, −0.2, 0, +0.1, +0.25, +0.4 (as SD1). Confirmatory: 6 doses × seeds
  42, 1, 2 = 18 models. Same pilot and negative-result rules as A2.
- **Predictions P10–P13** (from `docs/audit2/05_additions.md` §4.3; P8 and P9 are already
  used, so number from P10):
  - P10: exact ROAD lowers the random-vs-object preference at the lowest dose compared with
    black deletion, in each natural-image setting.
  - P11: exact ROAD still over-detects (FPR > 0.5) on Pet, or it does not; write the
    prediction one way, with the falsification rule.
  - P12: on the watermark, preference(S over O) rises with r_c (Spearman ρ > 0.8) for at
    least three of the four existing metrics.
  - P13: the watermark over-detection rate of black and blur deletion is above 0.5.
  Each prediction states its test, threshold, model set and what counts as "not testable".

**T2.2** Author uploads the amended file as a new Zenodo version and sends the DOI; an agent
records it in A3.

### Phase 3: SD3 exact ROAD

**T3.1 Code** (budget 1 day):
- Port the noisy linear imputation operator from https://github.com/tleemann/road_evaluation.
  Check its licence first and keep its copyright notice. Put it in `xai/road.py`.
- Add fills `road_morf` and `road_lerf` as new metric variants in `xai/metrics.py`, scored
  only by a new command (for example `dose_response.py road`) that writes new per-model files
  `per_model/*_road.csv`. Do not change the four existing metrics or their outputs.
- Unit test: on one small image, the imputation matches the reference implementation
  output to 1e-5 (vendor a tiny fixture produced by the reference code), and MoRF/LeRF
  orderings are correct.
- `analyze` adds ROAD to new tables only (`*_road.csv` and a new `summary.md` section).
- Kaggle notebook for S4 that runs `road` on the GPU settings, resumable per model.

**T3.2 Timing gate.** The author times 1 Pet model and 1 CIFAR ResNet-18 model on the laptop.
If one Pet model takes more than 15 min on Kaggle-equivalent hardware, reduce Pet to 25
images per model **before** the A3 upload, or record it as a dated A3 note before scoring.
