### Definitions

- Chance floor f = (100 − accuracy without shortcut) / (C − 1), C = number of classes: the reliance expected from errors alone (on a binary task every error on a conflicting image lands on the shortcut's class; with C classes 1/(C − 1) of errors if they spread uniformly). An approximation, since images without the shortcut are out of distribution.
- Chance-corrected reliance r_c = 100 (R − f) / (100 − f), in percent, not clipped (it can be slightly negative). Columns `classes`, `chance_floor`, `reliance_corrected` and `model_set` in `models.csv`.
- Decisions on r_c: positive class r_c > 50, 'metric says shortcut' = preference > 0.5. TPR = P(says shortcut | r_c > 50), TNR = P(says object | r_c ≤ 50), balanced accuracy = (TPR + TNR)/2, **over-detection rate** fpr = 1 − TNR. `_raw` columns: the same on raw reliance.
- Two-level bootstrap (2000 replicates, seed 0): models resampled within each dose, and each picked model's 100 images resampled independently; the same picks are reused for every comparison, metric and method (paired). 95% percentile intervals.
- Switch point (only for comparisons whose ideal crosses 0.5 at 50%: shortcut vs full / size-matched object): increasing isotonic fit (PAVA) of model preference on r_c, first r_c where the fit reaches 0.5 (linear interpolation). 'not identified' when no model lies within ±10 points. `switch_bracketed` (sensitivity): models within ±10 points on both sides; a switch inside a wider gap between models can be 'identified' from one edge but is not bracketed, and should not be quoted as located. 'identified at lowest-reliance edge': the switch lies within 5 points of the lowest-reliance model, i.e. the metric already prefers the shortcut near the bottom of the reliance range (over-detection), not a mid-range switch. The switch CI is empty when the full-data switch is undefined or fewer than half of the replicates cross. Sensitivity: 4-parameter logistic with free asymptotes (`switch_4pl_rc`). `switch_interp_rc`: the legacy first-crossing rule applied to r_c dose means.
- Effect size: per-image AUC gap g (positive = shortcut map rated better; AUC_B − AUC_A for deletion, AUC_A − AUC_B for insertion); medians at the lowest and highest dose in `effect_sizes.csv`.
- p-values come from two sources. Correlations (responsiveness, methods): Spearman's t approximation over the models of a setting, not from the bootstrap (the bootstrap gives only their intervals). Paired metric differences: two-sided percentile bootstrap, floored at 1/(reps + 1). Behaviour AUROC vs 0.5: z-test with the two-level bootstrap SE (not floored; the floored percentile value is `p_auroc_boot`); one-sided (H1: AUROC > 0.5) for the class-stratified AUROCs (`*_strat`, primary), two-sided with a `direction` column for the unstratified ones. BH and Holm within families: responsiveness:<comparison>, methods, metric_pairs:<comparison>, behaviour:<label> (each AUROC column adjusted separately). Headline Holm: one family over the union of the headline rows (shortcut vs full object and shortcut vs random responsiveness, and the pooled and within-model class-stratified one-sided primary behaviour AUROC for shortcut vs full object); `p_holm_headline` in the responsiveness table, `p_holm_headline_strat` and `p_holm_headline_within_strat` in the behaviour table. p < 0.001 is printed as '< 0.001'.

Validity limits (not fixable by new runs):
- PneumoniaMNIST: the 'object' map is the image's own intensities, and 97.5% of pixels exceed 0.1, so it is an intensity ranking of the whole radiograph, not an object segmentation.
- CIFAR-10 (both architectures): the 'object' map is a centred Gaussian prior, so Pet (real segmentation masks) is the primary natural-image evidence.
- Blur fill leaves about 20% (28 and 32 px) to 25% (Pet) of the patch intensity in place, so blur deletion does not fully remove a patch shortcut.
- `size_matched` takes the first k pixels of a stable descending sort of the object values; on MNIST many saturated pixels tie, so it picks the topmost saturated pixels in row-major order.

### MD4 per-image behavioural ground truth

Each scored aligned image gets a label from forward passes only. Primary (`follows_shortcut_causal`, reviewer 05's moved-shortcut design plus the shortcut-removed pass): 1 if the model predicts the shortcut's class when the same image's shortcut is moved to a wrong class's position and does not predict that class with the shortcut removed; 0 if the moved shortcut does not win; undetermined (excluded, `undetermined_rate`) if the model already predicts the shortcut's class without any shortcut (this takes precedence over the moved pass; the rare case moved → other class and removed → shortcut's class is also undetermined). The removed-pass rule keeps ordinary errors (on a binary task every error lands on the shortcut's class) from counting as shortcut use, the same floor r_c removes from reliance. Checks: `follows_shortcut` (moved-shortcut pass only) and `shortcut_dominant` (reviewer 03): Δ_S > Δ_O, with Δ_S = p_y(aligned) − p_y(no shortcut) and Δ_O = p_y(aligned) − p_y(another-class image with the label-y shortcut). The score is the per-image AUC gap (shortcut vs object). **Class-stratified AUROC (primary):** on the binary settings (PneumoniaMNIST, Pet) which images are undetermined and which are followed depends strongly on the image's true class (a model that fails without its shortcut predicts one class), and the AUC gap also differs by class, so an AUROC over images of both classes can fall far below 0.5 from class differences alone (Simpson's paradox). The primary statistics therefore compute the AUROC within each true class and average over the classes that have both labels: `auroc_pooled_strat` (images of all models pooled; still mixes between-model and within-model signal) and `median_model_auroc_strat` (per model, then median over models; detection inside one model; `models_with_both_labels_in_a_class` models contribute). Both have two-level CIs and one-sided z-test p-values (H1: AUROC > 0.5), so an AUROC below 0.5 is never significant. The unstratified `auroc_pooled` and `median_model_auroc` are kept as checks with two-sided p-values and a `direction` column; an unstratified value significantly below 0.5 means inverted ranking (on the binary settings, mostly a class effect), not detection. accuracy = mean(1 − |w − y|). calibration_gap = mean(preference − follow rate) (positive = over-detection). observed_switch_rc: r_c where the follow rate crosses 0.5 (isotonic), the derived ideal replacing the assumed 50%. **The per-image test is now primary; the aligned-image preference curves are secondary.**

### Metric responsiveness to reliance (oracle maps)

responsiveness_rho: Spearman correlation between reliance and preference for the shortcut map (ideal: close to 1). decision_accuracy: share of models where the preferred map matches whether reliance is above 50%. switch_point_reliance: reliance where preference crosses 0.5 (ideal: 50). comparison: which two oracle maps are compared (preference = share of images where the metric rates the first above the second). Size-matched object: a binary map of as many object pixels as the shortcut has, the first k of a stable descending sort of the object values (on MNIST many saturated pixels tie, so it takes the topmost saturated pixels in row-major order; on Pet, the k mask pixels nearest the mask centroid). Placebo: the shortcut's shape at a wrong class's position, which never carries evidence. Random: independent uniform scores per pixel (a fully random ordering). The placebo's non-patch pixels are tied and ordered randomly, so it behaves almost like the random map ('placebo vs random' stays near 0.5). 'Placebo vs full object' and 'random vs full object' should be LOW at low reliance; a rise at high reliance is correct, because the object map then explains the model worse than a random ordering. switch_ci_low/high and rho_ci_low/high: 95% bootstrap intervals (2000 resamples of the seeds within each dose). switch_found_share: share of resamples in which preference crosses 0.5 at all (the switch interval is left empty below 0.5).
